# 게임 개발 투입 가능성 평가와 우선순위 (2026-10-31)

외부 검토 세션(코드/문서 읽기 기반, 빌드·테스트는 직접 돌리지 않음)의 평가를 기록한다. 이 문서의 우선순위를 따라 진행하고, 항목을 끝낼 때마다 아래 "진행 현황" 표를 갱신한다.

## 한 줄 평가
기술 기반(렌더링, 고정 카메라 방, 충돌, 트리거, 에디터, 굽기, 플레이어, 스크립트 한 바퀴)은 탄탄하고 테스트도 두껍다. 그러나 지금은 "탐험 데모" 수준이다. SIGNALIS풍 게임에는 텍스트/HUD, 오디오, 오브젝트 생성/삭제, 세이브 등이 비어 있다.

## 구조상 주의
- 프레임 규칙이 C#(`PlaySession`)과 C++(`Scene`) 두 곳에 있다. 기능을 추가할 때마다 양쪽에 반영하고 교차 검증 테스트도 유지해야 한다. 에디터 Play 모드는 스크립트를 실행하지 않는다. 장기적으로 통합 방향(에디터가 `EngineScene`을 쓰거나 플레이어를 띄우기)을 정해 둔다.
- 새 기능은 항상 (1) 테스트 동반, (2) 결함 주입으로 테스트 실효성 확인, (3) `gge_player`를 실제로 띄워 눈으로 확인(창/키보드/게임패드 경로는 자동 테스트가 못 덮는다).

## 빈칸과 우선순위

| 순위 | 항목 | 근거 | 방향 |
|---|---|---|---|
| P1 | 실제 Blender `.glb` 파이프라인 검증 | 지금까지 코드로 만든 glTF로만 검증. 모델 앞쪽(+Z) 가정도 미확인(열린 결정 1) | 스킨/애니메이션 캐릭터 1개 + 방 모델 1개를 실제로 내보내 에디터/Bake/플레이어로 확인. 문제는 임포터/문서에 반영 |
| P2 | 오브젝트 쓰기 API 확장 | 스크립트는 위치 이동/알파만 가능 | `IScriptContext`와 `gge_scene_*`에 생성/삭제(프리팹 또는 씬 노드 복제), 표시 토글, 회전/크기, 클립 재생 전환 추가. **이름 있는 충돌체 + 켜기/끄기(잠긴 문)도 포함**(구현 세션 제안, `.ggs` 형식 변경 필요: 버전/호환, 독립 작성기, 퍼징, 에디터 이름 칸, C#/C++ 교차 검증 동반) |
| P3 | 텍스트/HUD/대화창 2D 패스 | 엔진에 font/text/2D 오버레이 없음 | 저해상도 RT 위 비트맵 폰트 쿼드. **한글 사용 여부를 먼저 결정**(폰트 아틀라스 방식이 달라진다). 스크립트 API: 텍스트 표시/대화창/HUD 항목 |
| P4 | 오디오 | 엔진에 오디오 없음 | 플레이어 쪽(XAudio2 또는 miniaudio). 효과음, BGM 루프, 볼륨. `IScriptContext.PlaySound` 등 |
| P5 | 세이브/로드 | 문서에 "세이브 없음" | 스크립트용 키-값 저장(진행 플래그, 인벤토리) |
| P6 | 수직 슬라이스 샘플 게임 | API를 상상으로 설계 중 | 방 3개, 열쇠/문 퍼즐, 대화 1~2개를 샘플 스크립트로 실제 제작해 빠진 것을 찾는다 |
| P7 | 씬/레벨 전환 | 씬 하나 = 프로세스 하나 | "게임 하나 = 씬 몇 개"로 갈지 결정 후 `LoadScene`과 상태 보존 |
| P8 | 전투 | 동적 충돌체/높이/다중 개체 트리거/적 AI/피격 판정 없음 | 장르 비중(탐험·퍼즐 vs 전투)을 먼저 결정. 전투 중심이면 큰 엔진 변경 |
| P9 | 룩/후처리 | fog, CRT/노이즈/스캔라인 없음 | 비용 대비 효과가 좋음. HUD 이후 |
| P10 | 배포/운영 | .NET 10 런타임 필요(자체 포함 미구현), 설정 파일/창 크기 조절 없음, 창 모드 스크립트 오류 시 종료, GDI 프레젠트(vsync 없음), 어댑터 선택 없음, **배포 `gge.dll`에서 테스트 훅 심볼(`gge_scene_set_spawn_failure_for_tests`) 제거 또는 `GGE_ENABLE_TEST_HOOKS` 가드** | 출시 전에 해결 |
